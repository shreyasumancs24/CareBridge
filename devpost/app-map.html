CareBridge · a source-grounded discharge-summary explainer

How the app fits together

CareBridge keeps the current document and results in page memory. The browser asks the app’s server route to explain the text; the route checks the provider response before sending a result back for display.

Reference route through the code

Use this short path to locate a future change. Search for the bold function names if your editor does not show line numbers.

  1. app/page.tsx · Home and explainInstructions
    The form validates the current text, sends an explain request, and stores only a validated response in page state. updateDocument clears results when the text changes.
  2. app/api/carebridge/route.ts · POST
    The server checks the request, adds the model instructions, calls Cloudflare Workers AI, and returns a generic safe error if the response cannot be accepted.
  3. lib/carebridge.ts · validation and response parsers
    This shared module enforces the text limit and checks response fields and exact source excerpts before the UI can display them.

To change this, start here

  • Input limit or shared response checks: lib/carebridge.ts.
  • Provider instructions, timeout, or safe server errors: app/api/carebridge/route.ts.
  • Page labels, results, and question history: app/page.tsx.
  • Colors and responsive layout: app/globals.css.

A practice to reuse

The 20,000-character boundary was treated as a hypothesis, then checked with a synthetic document through the real CareBridge route. That produced evidence about the complete request and response path, including the app’s excerpt validation. In another project, turn an uncertain limit or integration assumption into one safe, observable end-to-end check before treating it as settled.
